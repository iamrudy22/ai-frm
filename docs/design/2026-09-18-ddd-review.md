## 0. 요약

**도메인 모델이 없다.** 이벤트 스토밍으로 4단계 골격(수집→산출→판정→리포팅), 4개 지표, 용어집까지 뽑아놨지만 코드에는 반영돼 있지 않다. React 페이지 컴포넌트 두 개가 파싱·산식·판정·표현을 전부 떠안고 있다.

다만 이것은 PoC다. 전술 패턴을 전부 끌어오면 과설계다. 아래 6건 중 **지금 값을 하는 것은 D1·D2·D4**이고, D5·D6은 3단계(적정 시재)에 들어갈 때 효력이 생긴다.

## 1. 확정 — 등급 용어 (D1 해결)

**`정상 / 주의 / 경고 / 위기` 로 확정한다.** (2026-09-18)

문서 간에 표기가 갈려 있었다.

| 출처 | 1단계 | 4단계 |
|---|---|---|
| [대금회수 회의록](../meeting-notes/2026-09-09-daegeum-hoe-su-risk.md) · 현재 코드 | **정상** | **위기** |
| [이벤트 스토밍](../meeting-notes/2026-09-09-event-storming-2nd.md) 2-3 | 안전 | 위험 |

→ 이벤트 스토밍 문서의 `안전`·`위험` 표기는 **이 결정으로 대체된다.** 회의록은 그 시점의 기록이므로 원문을 고치지 않는다.

함께 정리할 명칭:

| 대상 | 확정 | 비고 |
|---|---|---|
| 지표명 | **대금 회수 위험** | 이벤트 스토밍 2-2의 `대금 회수 불능 위험`은 쓰지 않는다 |
| 경로·식별자 | **`payment-recovery`** | `daegeum-hoe-su`는 한글도 영어도 아닌 로마자라 도메인 용어로 기능하지 못한다 |
| 지표명 | **유동성 Gap** | 회의록의 `유동성 갭`과 혼용하지 않는다 |

보고서가 부서장에게 올라가는 산출물이므로 **화면 문구가 곧 도메인 용어**다. 4개 지표로 확장되기 전에 고정해 둔다.

## 2. D2. 원시값 집착이 이미 버그를 냈다

[수정 계획 §0의 문제 B](../plans/2026-09-18-yudongseong-gap-fix-plan.md)는 단순 실수가 아니라 **모델 부재의 증상**이다.

```ts
const v = readCell(sheet, 'K', 7);      // 금액 (억원)
const grade = v >= 0.9 ? '정상' : ...    // 비율로 취급
```

금액과 비율이 둘 다 `number`라 타입이 막아주지 못했다. 값 객체가 있었다면 컴파일 단계에서 걸렸다.

추가 증상:
- **단위(억원)가 코드에 없다.** `A2` 문자열 안에만 있어서, 원 단위 시트가 들어오면 조용히 틀린다.
- **등급 타입이 두 번 선언돼 있다.** `Grade`(payment-recovery 페이지)와 `GapGrade`(대시보드)가 글자까지 같은 유니온이다. 등급은 도메인의 단일 개념인데 정의가 둘이다.
- 기준월·회차가 문자열·숫자로 흩어져 있어 회차 순서 검증(수정 계획 §4-3)을 걸 자리가 없다.

## 3. D3. 인프라가 도메인까지 새어 들어온다

```ts
function computeGap(wb: XLSX.WorkBook): GapResult
```

**도메인 계산 함수가 xlsx 타입에 의존한다.** 가장 명백한 레이어 위반이다. 수정 계획 §3-3이 "계산 로직을 파싱에서 분리해야 테스트 가능하다"고 한 것도 결국 이 증상이며, Vitest 도입은 치료가 아니라 진통제다.

`TARGET_SHEET`·`L5`·`41행`(인프라 좌표)과 `GAP_BREAKPOINTS`(도메인 정책)가 같은 상수 블록에 나란히 있다. 엑셀 양식이 바뀌면 판정 규칙 파일이 흔들린다.

→ 수정 계획 §5(셀 탐색 전환)가 실제로 하려는 일은 **부패 방지 계층(ACL) 구축**이다. 그렇게 명명해야 성격이 드러난다.

## 4. D4. 애그리거트가 빠졌다 — "회차"

도메인의 진짜 덩어리는 **자금수지표 회차(Statement Revision)** 다. 기준일(`A2`) + 월별 계열 + 항목 계층이 하나로 묶이며, 여기에 불변식이 있다.

- `기초시재 + 수입계(6) − 지출(41) = 다음 달 기초시재` — 실물로 전 구간 검증됨
- `수입(7) = 정부출자금 + 국고보조금 + 국민주택기금 + 공공분양자금 + 분양회수 + 기타수입`
- 두 회차를 비교할 때 기준월은 1개월 차이

**수정 계획 §4-3의 회차 순서 검증을 UI에 붙이려 했으나, 회차를 애그리거트로 만들면 그것은 애그리거트 불변식이 된다.** 검증 지점이 한 곳으로 모이고, 화면이 늘어도 중복되지 않는다.

## 5. D5. 지표 4종이 동형인데 추상화가 없다

건설경기 인식 지수 · 대금 회수 위험 · 유동성 Gap · 적정 시재 — 넷 다 `값 산출 → 구간 판정 → 4단계 등급 + 코멘트` 구조다. 이벤트 스토밍 2-3이 "지표별 개별 단계 판정"이라고 명시했으므로 형태가 같다.

현재는 지표마다 함수·등급 타입·코멘트 맵이 따로다. 3단계(적정 시재 3개 모델 + 가중치)까지 가면 4벌이 된다.

→ `RiskIndicator` 공통 개념(이름·산출값·구간표·등급·코멘트)으로 모델링한다. **3단계 착수 시점에 한다** — 지표가 2개일 때는 추상화 이득이 비용보다 작다.

> **2026-09-28 재검토 — 공통 추상화를 하지 않는다.** 위의 "넷 다 4단계 등급" 전제가 틀렸다. 적정 시재에는 등급이 없다. T/F와 '안정적'/'적정시재 부족' 표기뿐이다([적정 시재 PRD](../plans/2026-09-28-jeokjeong-sijae-prd.md) §9-6). 판정 형태가 4단계와 T/F로 갈리므로 `RiskIndicator` 하나로 묶으면 한쪽에 맞지 않는 칸이 생긴다.
>
> 대신 **지표별로 분리**했다([지표 분리 계획](../plans/2026-09-28-jipyo-bunri-plan.md)).
> - `risk/<지표>/`에 산식과 정책을 함께 둔다.
> - 등급 어휘·구간 판정 도구(`grade.ts`)는 등급을 쓰는 두 지표만 쓴다.
> - 경계는 `src/boundaries.test.ts`가 지킨다. 지표 간 import 금지, 등급 없는 지표의 `grade` import 금지.
> - 지표를 엮는 일은 `application/dashboard.ts`가 맡는다. 한 지표의 실패가 다른 지표로 번지지 않는다.

## 6. D6. 판정 정책의 정본이 엑셀에 있다

이벤트 스토밍 6장 1번이 아직 열린 질문이다 — *"4개 지표 각각의 점수 산식과 구간 기준을 그대로 옮겨 쓸 수 있게 문서화할 수 있는가"*. 그리고 2-3에 *"각 지표의 점수 기준표는 해당 엑셀 시트 안에 들어 있다"*.

**도메인 정책의 정본이 엑셀인데 코드에 상수로 박으면 이중화된다.** 1단계 계획 §5-4도 "이후 외부 설정으로 빼서 교체 가능하게"라고 이미 인식하고 있다.

→ 정책을 명시적 객체(`policy.ts`)로 분리하고 **출처를 주석에 고정**한다. 현재 정본은 회의록이다(수정 계획 §2-4). 엑셀 기준표를 받으면 그쪽으로 옮긴다.

> **2026-09-28**: 정책을 코드에서 떼어 내는 것에 더해 **정책끼리도 떼어 냈다.** 한 파일이던 `risk/policy.ts`를 `risk/<지표>/policy.ts`로 나누고, 공용 코멘트 표·`IndicatorKey`를 없앴다. 적정 시재 정책은 LCR 가중치와 두 표기뿐이다. 엑셀 기준표 이관(아래 미결)은 여전히 남아 있다.

## 7. 제안 구조

PoC 규모에 맞춰 최소한만 잡는다.

```
src/

    risk/
      grade.ts             등급 값 객체 + 구간 판정 (단일 정의)
      indicator.ts         지표 공통 개념           ← D5, 3단계에서
      payment-recovery.ts  대금 회수 위험 산식
      liquidity-gap.ts     유동성 Gap 산식
      policy.ts            구간 기준표 — 출처 명시
    cashflow/
      statement.ts         회차 애그리거트 (기준월, 월별 계열, 불변식)
  infrastructure/
    xlsx/
      statement-reader.ts  ACL: xlsx → Statement. 시트명·라벨·열 탐색 전담
  app/aifrm/page.tsx       표현만
```

### 합격 기준

**`domain/` 아래에 `import ... from 'xlsx'`가 한 줄도 없을 것.**

이것만 지키면 수정 계획 §3-3의 테스트 5개가 fixture 없이 자연히 돌아간다. 레이어가 지켜졌는지를 한 줄로 확인할 수 있다.

### 넣지 않을 것

Repository · 도메인 이벤트 · CQRS · 의존성 주입 컨테이너. 지금은 저장소도 없고 상태 변경도 없다. 이력 저장이나 보고서 자동 생성(로드맵 ②)이 들어올 때 다시 판단한다.

> **2026-09-28 재판단**: 건설경기 인식 지수가 **분양회수 계획·실적 이력**을 저장하게 되어 Repository를 넣는다(§10). 도메인 이벤트·CQRS·DI 컨테이너는 여전히 넣지 않는다.

## 10. 2026-09-28 — 건설경기 인식 지수 반영

네 번째 지표를 설계하면서 위 원칙을 다시 적용했다. 근거 문서는 [정책](../plans/2026-09-28-geonseol-gyeonggi-policy.md)과 [구현 계획](../plans/2026-09-28-geonseol-gyeonggi-impl-plan.md)이다.

### 10-1. 용어 확정 (D1과 같은 작업)

| 대상 | 확정 | 쓰지 않는 표기 |
|---|---|---|
| 지표명 | **건설경기 인식 지수** (이벤트 스토밍 표기) | 건설경기인식지수, 재무위기인식지수(엑셀 시트명) |
| 산출값 | **종합위기인식지수** | 지수, 점수 합계 |
| 판정 | **종합위기단계**. 어휘는 `정상/주의/경고/위기`로 다른 지표의 `Grade`를 공유하고, 화면 표기만 "단계"로 한다 | 위기등급 |
| 판정 불가 | **산출불가**. 코드는 `kind: 'unavailable'` | 계산 불가, N/A |
| 식별자 | **`construction-perception`** | `construction-sentiment`(sentiment는 '심리'라 '인식'과 뜻이 다르다) |
| 저장 대상 | **분양회수 계획·실적 이력**. 코드는 `ForecastLedger` | 분양회수data(엑셀 시트명), 원장 |

### 10-2. 분양회수 계획·실적 이력은 회차 쪽 애그리거트다

이력에 쌓이는 것은 "각 회차가 적은 분양회수 계획과 실적"이다. 특정 지표의 개념이 아니라 **자금수지의 사실**이다. 대금 회수 위험(u월 회차의 u월 계획 대비 u월 실적)도 같은 이력의 두 칸이다. 그래서 `domain/cashflow/`에 둔다. 지표 폴더에 두면 규칙 1 때문에 다른 지표가 쓸 수 없다.

애그리거트로 만드는 이유는 불변식이 있어서다.
- 칸마다 쓸 수 있는 회차는 하나다. u월 실적은 u+1월 회차, u월 계획은 u월 회차만 쓴다.
- 나중 회차는 과거 실적을 덮지 않는다.
- 변경은 `record(회차 기재분)` 하나로만 한다.

### 10-3. Repository와 포트

- `application/`에 포트 두 개를 둔다. `ForecastLedgerRepository`(이력 저장)와 `EconomicIndicatorSource`(ECOS)다. 구현은 `infrastructure/`가 한다. 규칙 4(유스케이스는 판독 계층을 모른다)는 이 의존성 역전으로 지킨다.
- 흐름 조율은 유스케이스 두 개가 맡는다. **회차 반영**과 **건설경기 인식 지수 산출**이다. 화면은 결과만 표시한다. D3에서 걷어 낸 "화면이 흐름을 떠안는" 구조가 비동기 입력과 함께 돌아오지 않게 한다.
- 조립(포트에 구현을 끼우는 일)은 `app/api/**/route.ts`가 한다. DI 컨테이너는 쓰지 않는다.

### 10-4. ECOS는 ACL이 끝까지 번역한다

`infrastructure/ecos`가 통계표 코드, `TIME='202607'`, 문자열 `DATA_VALUE`, `UNIT_NAME`을 `지표 → 달력 월별 값·단위·최신월`로 바꿔 넘긴다. 자금수지표의 `statement-reader`가 xlsx를 `Statement`로 완결해 넘기는 것과 같은 역할이다. 도메인과 화면은 ECOS 형식을 모른다.

엑셀 `분양회수data`를 옮기는 시드 스크립트도 레거시 ACL이다. 날짜 라벨을 한 달 당기는 보정은 그 스크립트 한 곳에만 둔다.

### 10-5. 정책은 표다 (D6)

점수화 기준은 지표별 함수가 아니라 **엑셀 IF문을 옮긴 데이터 표**로 둔다. 표의 열은 변환·방향·만점·영점·영점 경계(포함/제외)·가중치다. 산식 파일에는 이 표를 해석하는 함수 하나만 둔다. 이렇게 하면 엑셀 기준표를 정본으로 옮길 때 줄 단위로 대조할 수 있다.
