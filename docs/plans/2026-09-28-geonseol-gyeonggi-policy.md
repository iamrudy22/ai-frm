## 0. 한 줄 요약

매월 경제지표 10종(ECOS 9종 + 사내 분양회수 1종)을 **변화율 → 0~1 점수 → 가중합**으로 바꿔 **종합위기인식지수(0~100.47)** 를 내고, 20/40/60 구간으로 **정상·주의·경고·위기** 4단계를 판정한다.

| 용어 | 정의 |
|---|---|
| 원값 | 지표의 월별 원자료 (L1) |
| 변화율 | 원값을 지표별 방식(전월대비·전년동월비·3개월 누적)으로 바꾼 값 (L2) |
| 점수 | 변화율을 0(위험 없음)~1(최대 위험)로 선형 클리핑한 값 (L3) |
| 종합위기인식지수 | Σ(가중치 × 점수) (L4) |
| 종합위기단계 | 지수의 구간 판정. 정상/주의/경고/위기 (L5) |
| 산출불가 | 결측이 있어 지수와 단계를 내지 않은 상태 (§6-1) |
| 분양회수 계획·실적 이력 | 올린 회차마다 뗀 분양회수 실적과 3개월 계획. 산출 요청마다 새로 만든다 (§3-3) |

용어와 코드 식별자(`construction-perception`)는 [DDD 검토 §10-1](../design/2026-09-18-ddd-review.md)에서 확정했다. 화면·문서의 지표명은 **건설경기 인식 지수**로 띄어 쓰고, 판정은 **종합위기단계**로 적는다.

## 3. 산식

### 3-1. 변화율 (L2) — ECOS 9종

`v[t]`는 t월의 원값이다.

| 변환 | 산식 |
|---|---|
| 전월대비 | `(v[t] − v[t−1]) / v[t−1]` |
| 전년동월비 | `(v[t] − v[t−12]) / v[t−12]` |
| 대출금리(6번) | `(v[t] − v[t−1]) × 100` — 비율이 아니라 **%p 차이 × 100 = bp**다 |

### 3-2. 분양회수 예측오차 (7번) — 자금수지표에서 계산

> **2026-09-28 재개정 (확정).** 한때 자금기획팀 서술대로 "(7월 회차 4·5·6월 실적 − 5월 회차 6·7·8월 계획) ÷ 5월 회차 5·6·7월 계획"으로 구현했으나, 엑셀 `분양회수data`(이미지로 확인)와 창이 달랐다(7월 36.06% vs 11.35%). 원인은 엑셀 행 라벨이 한 달 밀려 있어서다 — 엑셀 "2026/05" 행의 계획 M0~M2는 **4월 회차**의 4·5·6월 계획이다(§7 D8). 서술은 이 라벨을 그대로 읽은 것이었다. 자금기획팀과 확인해 엑셀 `분양회수data` G열 식과 같은 창인 아래 정의로 확정했다.
>
> **2026-09-28 실적 출처 확정.** 실적을 각 달의 직후 회차에서 읽어(회차 네 개) 엑셀 H열 값까지 맞췄으나, 자금기획팀이 **N월 기준에는 N월 수지표 한 장의 실적과 N−3월 수지표의 계획만 쓴다**고 확정했다. 회차는 두 개면 된다.

라벨 t의 오차율:

```
실적      = t월 회차에 적힌 (t−3, t−2, t−1)월 분양회수 실적 합
계획      = t−3월 회차의 (t−3, t−2, t−1)월 분양회수 계획 합 (엑셀의 M0 + M1 + M2)
오차율    = (실적 − 계획) ÷ 계획
```

8월이면 (8월 회차의 5·6·7월 실적 − 5월 회차의 5·6·7월 계획) ÷ 5월 회차의 5·6·7월 계획이다. 엑셀 `분양회수data` G10 = `SUM(C10:C12) − SUM(D12:F12)`("2026/08" 행)과 같은 창이다.

- **N월 기준(최신 회차 N, 기준월 N−2)에는 N월 회차의 실적과 N−3월 회차의 계획을 쓴다.** 기준월 b로 말하면 **b+2 행**이다(2026-09-28 결정). 8월 기준이면 23.35%, 기준월 6월 지수에 쓴다.
- **값은 엑셀 H열과 다를 수 있다.** 엑셀 C열은 각 달 실적을 그 달 직후 회차에서 적어 두고 고치지 않는다(5월 실적은 6월 회차, 6월 실적은 7월 회차에서). 앱은 N월 회차에 적힌, 뒤에 고쳐진 값을 쓴다. 2026년 회차로 4~8월이 41.68 / 45.90 / 26.07 / 13.84 / 23.35%, 엑셀은 38.89 / 42.99 / 24.75 / 11.35 / 24.11%다(차이 −0.76~+2.91%p). 오차율 1%p는 점수가 붙는 구간(−40%~0%)에서 지수 약 0.08점이다.
- 엑셀 `위기단계` 시트는 기준월 b에 b+1 행을 쓴다(6월 지수에 "2026/07" 행). 이 지표는 b+2 행이라 한 달 다르다.
- **필요한 회차는 b−1월(계획)과 b+2월(실적) 두 개**다. 8월 기준이면 5·8월이다(§5).
- **읽는 항목**: 자금수지표 `분양회수` 행. 1·2월 회차는 `잠정운영기준`, 3월 회차부터 `본운영반영` 시트.
- **검증**: 2026년 1~8월 회차 파일로 4~8월 값을 위 값으로 고정한다. 창이 엑셀과 같은지는 실적만 직후 회차 값으로 바꿔 넣었을 때 엑셀 H열과 0.003%p 안에서 같아지는 것으로 확인한다(엑셀 실적 칸의 반올림 차이).
- **전년도 달**: 1~3월 회차는 시트가 그해 1월부터라 전년 10~12월 실적 열이 없다. 그 회차가 실적 회차인 기준월(전년 11월~1월)은 산출불가다. 어디서 받을지는 첫 1월 회차를 보고 정한다(구현 계획 R7).

### 3-3. 분양회수 계획·실적 이력 — 올린 회차로 그때그때 만든다

한 기준월에 회차 두 개(t−3월 계획, t월 실적)가 필요하고, 과거 계획은 최신 회차에 남아 있지 않다. 그래서 **산출할 때 필요한 회차를 모두 올린다.** 올린 회차마다 기재분 한 건을 떼고, 이력의 단위는 달이 아니라 **회차**다.

**저장하지 않는다(2026-09-28 변경).** 이력은 산출 요청마다 그 화면에 올린 회차들로 새로 만들고 버린다. 전에 올린 파일이 결과에 섞이지 않는다. 값을 남기는 일은 별도 기능(스프레드시트 기록)으로 다룬다.

기준월 b인 회차(예: 7월 회차)에서 떼어 두는 것:

| 떼어 두는 값 | 7월 회차의 예 | 쓰이는 곳 |
|---|---|---|
| 그 시트의 실적 전부 | 1~6월 실적 | 그중 4·5·6월이 "2026/07" 창(7월 기준, 기준월 5월)의 실적 |
| 그달부터 계획 | 7·8·9월 계획(M0~M2, 넷째 칸은 판형 호환용) | "2026/10" 창(10월 기준, 기준월 8월)의 계획 |

- **같은 회차를 두 번 올리면** 화면에서는 나중 파일을 쓴다. 한 요청에 같은 회차가 두 번 오면 서버는 거부한다.
- **회차에 없는 달**(전년 달 실적, 다음 해 열이 없는 계획)은 비워 두고 사유를 남긴다. 0으로 채우지 않는다.
- **실적은 t월 회차 한 장의 값**이다. 같은 달 실적이 다른 회차에 다르게 적혀 있어도 다른 회차에서 채우지 않는다. t월 회차 시트에 그 달 열이 없으면(1~3월 회차의 전년 달) 결측이다.
- **과거 달**: 해당 회차 파일을 올려야 산출된다. 올리기 전에는 산출불가이고, 어느 회차를 올릴지 알린다(2026-09-28 결정 (가)). 앱은 엑셀 `분양회수data` 시트를 읽지 않는다.
- 이 이력은 특정 지표가 아니라 **자금수지의 사실**이라 `domain/cashflow`에 둔다.

### 3-4. 점수 (L3)

모든 점수는 0~1이다. `r`은 §3-1·§3-2의 결과다.

| # | 지표 | 1점 | 0점 | 그 사이 |
|---|---|---|---|---|
| 1 | 총수주액 | `r ≤ −60%` | `r ≥ 0%` | `r / −60%` |
| 2 | 주택매매가격지수 | `r ≤ −1.5%` | `r ≥ 0%` | `r / −1.5%` |
| 3 | 미분양주택현황 | `r ≥ 30%` | `r ≤ 10%` | `(r − 10%) / 20%` |
| 4 | 주택건설인허가실적 | `r ≤ −60%` | `r > 0%` | `r / −60%` |
| 5 | 설비투자지수 | `r ≤ −10%` | `r ≥ −5%` | `(r + 5%) / −5%` |
| 6 | 대출금리 | `r ≥ 60bp` | `r ≤ 20bp` | `(r − 20) / 40` |
| 7 | 분양회수 예측오차 | `r ≤ −40%` | `r ≥ 0%` | `r / −40%` |
| 8 | 환율 | `\|r\| ≥ 7%` | `\|r\| ≤ 3%` | `(\|r\| − 3%) / 4%` |
| 9 | 주가 | `r ≤ −15%` | `r ≥ −5%` | `(r + 5%) / −10%` |
| 10 | 선행지수 순환변동치 | `r ≤ −0.6%` | `r > −0.2%` | `(r + 0.2%) / −0.4%` |

- 판정 순서는 엑셀과 같다. **1점 조건을 먼저**, 그다음 0점 조건, 둘 다 아니면 선형식이다.
- 4번과 10번만 0점 조건이 `>`(초과)다. 그러나 **결과는 `>=`와 같다.** 경계값에서 `>`가 거짓이면 선형식으로 넘어가는데, 선형식이 영점에서 정확히 0을 내기 때문이다(인허가 `0/−60% = 0`, 선행지수 `(−0.2%+0.2%)/−0.4% = 0`). 모든 점수 함수가 연속이라 부등호 차이는 결과에 드러나지 않는다. 그래서 정책 표에 따로 적지 않는다(2026-09-28 W2에서 확인).
- 3·5·9·10번은 0점 구간이 0에서 떨어져 있다. 이 정도 변동은 정상으로 본다는 뜻이다.

### 3-5. 종합위기인식지수 (L4)

```
종합위기인식지수 = Σ_{i=1..10} 가중치_i × 점수_i
```

가중치 합이 100.474이므로 이론상 최댓값은 100.474다.

### 3-6. 종합위기단계 (L5)

| 종합위기인식지수 | 단계 | 수치 |
|---|---|---|
| `< 20` | 정상 | 0 |
| `20 이상 40 미만` | 주의 | 1 |
| `40 이상 60 미만` | 경고 | 2 |
| `60 이상` | 위기 | 3 |

- 경계값은 **위 단계**에 넣는다. 지수가 정확히 20이면 주의다. 공용 도구 `risk/grade`의 `defineBands`(`atLeast`, 경계 포함)로 그대로 표현된다.
- 엑셀은 `L ≤ 100`일 때만 위기를 주고 100 초과면 빈칸을 낸다. 이 상한은 **두지 않는다**(§7 D2). 전 지표가 만점일 때 판정이 비는 것은 명백한 결함이다.

## 5. 기준월

> **2026-09-28 개정.** 처음에는 데이터가 기준월을 정했다(지표별 최신월 중 가장 이른 달). 지금은 **회차와 사용자가 정한다.** 계획: [기준월 선택·회차 연동](./2026-09-28-geonseol-gyeonggi-base-month-plan.md).
>
> **2026-09-28 결정.** 회차를 올렸을 때의 기본값은 **최신 회차 − 2개월**이다(`ROUND_LAG_MONTHS`). **8월 기준(최신 회차 8월)이면 6월, 7월 기준이면 5월.** 분양회수 예측오차는 N월 기준에 N월 회차의 실적과 N−3월 회차의 계획을 써서 회차 두 개면 된다(§3-2). ("최신 회차의 달", "최신 회차 − 1"을 거쳐 정했다.)

**기준월 = 최신 회차 − 2개월.** 사용자가 다른 달로 바꿀 수 있다.

| 기준월을 정하는 것 | 우선순위 | 예 |
|---|---|---|
| 사용자가 고른 달 | 1 | 2026/05를 고르면 5월 |
| 최신 회차 − 2 | 2 | 8월 기준이면 6월, 7월 기준이면 5월 |
| 오늘이 속한 달 − 2 (회차 없이 볼 때) | 3 | 9월에 열면 7월 |

- **N월 기준에 필요한 회차는 N−3·N−1·N월 세 개**다. 8월 기준이면 분양회수 5·8월, 대금 회수 위험 7·8월, 유동성 Gap·적정 시재 8월이라 **5·7·8월 회차 세 개로 모든 지표가 채워진다.**
- 건설·주택 통계는 익월 말에 수록되므로 N월 회차를 올릴 즈음에는 N−2월까지 온전히 나와 있다. 기준월을 앞당겨 고르다 공표 전인 달이 되면 그 지표는 "공표 전"으로 산출불가다. 이전 달로 옮기지 않는다.
- **보고 시차 2개월**(`REPORT_LAG_MONTHS`)은 회차 없이 볼 때만 쓴다. 건설·주택 통계가 익월 말에 수록되므로, 보고하는 달에는 두 달 전까지가 온전히 나와 있다.
- **연동 대상은 회차 기준월**이다. 화면의 자금수지표 기준월 선택(유동성 Gap·적정 시재용)은 따르지 않는다. 그 선택은 계획 달(9·10월…)까지 고를 수 있어서, 따라가면 건설경기 기준월이 공표 전인 달로 밀린다. 건설경기 카드에는 자기 선택 상자가 따로 있다.
- **고를 수 있는 범위**: 2016/03(분양회수 이력으로 산출되는 첫 달)부터 오늘이 속한 달의 전달까지. 범위 안이라도 값이 없으면 산출불가다.
- **새 회차를 올리면** 선택을 기본값(최신 회차 − 2)으로 되돌린다.

기준월을 정한 뒤에는 **그 달 하나만** 산출한다. 그 달에 빈 값이 있으면 이전 달로 **거슬러 내려가지 않고** `산출불가`를 낸다(§6-1). 거슬러 내려가면 결국 직전 확정월을 조용히 보여 주는 것과 같아진다. 이 방식은 §9-1 Q2에서 쓰지 않기로 했다.

**"공표 전"과 "빠졌다"를 가른다.** 기준월(또는 비교 월)이 그 지표의 ECOS 최신월보다 뒤면 "아직 공표 전입니다(최신 YYYY/MM)", 아니면 "값이 없습니다"다. 기준월을 앞당겨 고르면 공표 전일 수 있다. 조치가 다르므로(기다린다 / 확인한다) 사유를 나눠 보인다.

**과거 달은 지금의 ECOS 값으로 계산한다**(§6-2). 그때 보고한 값과 다를 수 있다는 점을 화면에 알린다.

- **화면에는 기준월 한 달만** 보여 준다(확정). 그 달의 지수·단계와 지표별 원값·변화율·점수·기여도를 낸다. 월별 추이 표는 내지 않는다.

## 6. 결측·수정 데이터

### 6-1. 결측은 0이 아니다 (확정)

값이 없는 지표는 결측으로 다룬다. 결측이 하나라도 있는 월은

- 결측 지표의 점수를 내지 않고,
- 종합위기인식지수와 단계를 내지 않으며,
- 단계 자리에 **`산출불가`** 를 표시하고 **어느 지표가 비었는지** 함께 알린다.

직전 확정월의 단계를 대신 보여 주지 않는다.

엑셀의 2026/07 행은 10칸 중 1칸만 채워졌는데 지수 68.4 **"위기"** 로 나온다. 빈칸이 0으로 계산되어 여섯 지표가 −100%로 만점을 받았기 때문이다. 이 지표에서 가장 먼저 막아야 할 사고다.

결측 판정은 **변화율의 입력 전체**에 적용한다. 당월 값뿐 아니라 전월(전월대비), 12개월 전(전년동월비), 분양회수 이력의 해당 칸(§3-3)이 없어도 결측이다. ECOS 호출 실패도 결측이다. 실패를 0으로 채우지 않는다.

화면에 `산출불가`가 뜨는 경우는 다음과 같다.

- 고른 기준월이 아직 공표 전일 때(사유: 공표 전).
- ECOS 호출이 실패한 지표가 있을 때.
- 분양회수에 필요한 회차를 올리지 않은 경우. 예를 들어 기준월 6월(8월 기준)에 5월 회차(계획)나 8월 회차(실적)가 없으면 산출불가다. 사이 회차(6·7월)는 없어도 된다.

### 6-2. 값이 바뀌면 최신 값을 쓴다

- **잠정치.** 국내건설수주액과 설비투자지수는 최근 2개월이 잠정치다. 엑셀의 수주액 2026/04~06 값은 ECOS 현재 값보다 9.7~14.3% 작다(2026-09-28 API 조회로 재확인).
- **기준연도 개편.** 설비투자지수는 엑셀이 `2015=100`, ECOS가 `2020=100`이다. 전 기간 값이 다르다. KB지수도 표기가 `2022.01=100`에서 `2026.01=100`으로 바뀌었다.
- 원칙: **ECOS 값은 매번 원천의 현재 값을 쓴다.** 단위 문자열은 코드에 박지 않고 응답의 `UNIT_NAME`을 그대로 보여 준다.
- **영향 (2026-09-28 API 대조)**: ECOS 현재 값으로 다시 계산하면 과거 126개월 중 6개월의 단계가 엑셀과 다르고, 지수 차이는 최대 14.5점이다. 자세한 목록은 [구현 계획 §14 R1](./2026-09-28-geonseol-gyeonggi-impl-plan.md)에 있다.
- 따라서 같은 달의 지수도 조회 시점에 따라 달라질 수 있다. 화면이 기준월 한 달만 보여 주므로 과거 월의 재계산 결과는 드러나지 않는다. 과거 보고값의 보관은 이번 범위에 넣지 않는다.

자동화는 월을 원천(회차의 기준월)에서 바로 붙이므로 라벨 문제가 생기지 않는다. `fixture_expected.csv`의 `score_분양회수예측오차`와 지수는 그대로 기대값으로 쓸 수 있다. 다만 `raw_분양회수예측오차` 열은 `기초데이터` H열에서 뽑혀 한 달 어긋나 있으므로, 7번 지표의 변화율을 검증할 때는 이 열 대신 점수에서 거꾸로 확인하거나 원천에서 다시 만든다.

## 8. 검증 기준

- 엑셀의 원값·오차율을 넣었을 때 2023/08~2026/06 35개월의 **종합위기인식지수가 소수점 6자리까지**, **단계 문자열이 전부** 엑셀과 일치한다. (`fixture_expected.csv`)
- 2026/07은 일치 대상이 아니다. **"위기"가 아니라 결측 9종을 알리는 `산출불가`** 가 나와야 한다(§6-1).
- 분양회수 예측오차: 2026년 1~8월 회차 파일로 계산한 4~8월 값을 고정한다(§3-2). 창은 실적만 직후 회차 값으로 바꿔 넣었을 때 엑셀 H열과 0.003%p 안에서 같아지는 것으로 검증한다. 앱 값은 N월 회차 실적을 써서 엑셀 H열과 다를 수 있다.
- ECOS 원값은 엑셀과 다를 수 있다(§6-2). 엑셀 일치 검증은 **엑셀 원값을 넣은 산식 테스트**로 하고, API 연동은 응답 파싱·결측·오류 처리만 따로 테스트한다.
- 경계 단위 테스트: 지수 20·40·60 정각, 4번·10번의 0점 경계가 0점임(`>`가 결과를 바꾸지 않음), 환율의 음수 변화율(절대값), 대출금리의 bp 단위.
- 실물 원값이 필요한 통합 테스트는 fixture 파일이 있을 때만 돈다. 이 저장소의 다른 지표와 같다.

## 부록 A. ECOS Open API 인증키 발급

무료이고 신청하면 바로 나온다. 2026-09-28에 신청 화면을 확인했다.

1. https://ecos.bok.or.kr/api/ 에 접속한다.
2. 위 메뉴 **서비스 이용 → 인증키 신청**을 누른다. 주소는 `https://ecos.bok.or.kr/api/#/AuthKeyApply`다.
3. **1단계 약관동의**: "경제통계 Open API 이용약관(필수)"과 "개인정보 수집이용 동의(필수)"에 동의하고 **다음**을 누른다. 회사명 정보제공은 선택이다.
4. **2단계**: 회원 정보(아이디·비밀번호·이메일 등)와 이용 목적을 입력한다. 이 인증키 신청이 곧 회원가입이다.
5. **3단계**: 신청이 끝나면 인증키가 발급된다. 로그인 후 **MyPage**에서 다시 확인할 수 있다.
6. 키를 서버 환경변수로 넣는다. 로컬 개발이면 `ai-frm/.env.local`에 한 줄을 추가한다. 이 파일은 커밋하지 않는다.
   ```
   ECOS_API_KEY=발급받은키
   ```
7. 동작 확인: 브라우저 주소창에 아래 주소를 넣어 JSON이 나오면 된다. `RESULT` 키가 보이면 실패이며, `ERROR-100`·`ERROR-101`은 키 문제다.
   ```
   https://ecos.bok.or.kr/api/StatisticSearch/발급받은키/json/kr/1/10/901Y020/M/202601/202607/I42A
   ```

2·3단계의 정확한 화면 문구는 신청하면서 확인한다. 이 문서는 1단계 화면까지만 직접 확인했다.

### 9-3. 구현 중 확인·변경 (2026-09-28)

| 항목 | 내용 |
|---|---|
| 4번·10번의 `>` 경계 | 결과를 바꾸지 않는다. 선형식이 영점에서 정확히 0이라 `>=`와 같다(§3-4). 정책 표에 경계 열을 두지 않았다 |
| 1~3월 회차 | 회차 시트가 계획연도 1월부터라 전년 달 실적을 뗄 수 없다. 그 회차가 실적 회차인 기준월(전년 11월~1월)이 산출불가로 드러난다. 조용히 틀린 값을 내지 않는다. 전년 달 실적을 어디서 받을지는 첫 1월 회차를 보고 정한다(구현 계획 R7) |
| ECOS "데이터 없음" 코드 | 인계 문서의 `ERROR-200`이 아니라 실제로는 `INFO-200`이다(키 오류도 `INFO-100`) |
| 검증 범위 | 인계 fixture 36개월에서 엑셀 127개월 전체로 넓혔다. 산출불가는 2026/07(ECOS 미입력)과 2016/01·02(이력 부족, D9)뿐이다 |
| 분양회수 예측오차 | 자금기획팀 서술 식(36.06%)으로 바꿨다가, 엑셀 행 라벨이 한 달 밀린 것을 읽은 서술임을 확인하고 **엑셀 `분양회수data`와 같은 창으로 재개정**(§3-2). 이력은 회차 단위(판형 2) 그대로 |
| 분양회수 실적 출처 | 엑셀 H열 값까지 맞추려고 각 달 실적을 직후 회차에서 읽었으나(회차 네 개), 자금기획팀 확인으로 **N월 회차 한 장의 실적**으로 바꿨다(§3-2). 회차 두 개면 되고, 값은 엑셀 H열과 −0.76~+2.91%p 다르다(2026년 4~8월). 1~3월 회차의 전년 달 실적은 다른 회차에서 채우지 않고 결측으로 둔다 |
| 기준월 규칙 | 데이터 기준(지표별 최신월 중 가장 이른 달)에서 **보고월 − 2개월 + 사용자 선택**으로 바꿨다가, "최신 회차의 달", "최신 회차 − 1"을 거쳐 **최신 회차 − 2 + 사용자 선택**으로 정했다(§5). 8월 기준이면 6월. 분양회수는 b+2 행이라 N월 기준에 N월·N−3월 회차 두 개면 된다 |
| 운영 준비(Q8) | ECOS 인증키 발급·설정 완료. 절차는 부록 A와 `ai-frm/README.md` |
| 이력 저장 폐지 | 서버 파일(`data/forecast-ledger.json`)에 회차를 쌓던 방식을 없앴다. 화면에 올린 회차만으로 매번 계산한다 |
