## 1. 실물 시트 검증 결과 (2026-09-18)

`2026년 8,9,10월 계획 ★01-01. 2026 본운영계획 자금수지표(0818_v1)_법인세추가.xlsx` / 시트 `12_26년자금수지표(본운영반영)` (`A1:AO168`) 확인 완료. 이전 세션의 셀 선택은 **전부 맞았다.**

### 1-1. 회의록 169% 재현 ✅

| 항목 | 셀 |
|---|---|
| 기초시재 | `L5` |
| 3개월 지출 (8·9·10월) | `L41+M41+N41` |
| 3개월 수입 (8·9·10월) | `L7+M7+N7` |
| **Gap** | 기초시재 ÷ (지출 − 수입) = **169.0% → 정상** |

[회의록](../meeting-notes/2026-09-09-daegeum-hoe-su-risk.md)의 *"보유 자금은 순지출 대비 169%"* 와 일치한다. 같은 회의록의 적정시재 수치 `16,011`도 `L7`(8월 수입)과 일치해 8월=L열, 7행=수입임이 교차 확인됐다.

> 실수치는 이 저장소에 기록하지 않는다(§2-5). 확인된 것은 **셀 위치와 산출 결과 169.0%** 이며, 169%는 이미 회의록에 있는 값이다.

### 1-2. 행 구조

| 행 | A열 라벨(원문) | 성격 |
|---|---|---|
| 5 | `기초시재` | 월초 잔고 |
| 6 | `수입계(자금조달포함)` | 총유입 (조달 포함) |
| 7 | `수입` | 조달 제외 유입 |
| 41 | `지출` | **양수 저장** |

**지출은 양수**다. 따라서 `순지출 = 지출 − 수입`이 맞고, §4의 `abs` 제거 방향이 옳다. (M2 해소)

시재 롤포워드도 검증됐다 — `기초시재 + 수입계(6) − 지출(41) = 다음 달 기초시재`가 K→L→M→N 전 구간에서 정확히 성립한다. 즉 **6행이 회계상 총유입이고, 7행은 조달을 뺀 부분집합**이다.

### 1-3. ⚠️ `수입` 라벨 완전 일치 필수 (M3 해소)

`A6 = "수입계(자금조달포함)"` 이 문자열 `수입`을 **포함**한다. 부분 일치로 탐색하면 위에 있는 6행을 먼저 집어 **조달 미포함 결정이 조용히 뒤집힌다.** 반드시 완전 일치로 매칭한다.

### 1-4. ⚠️ 월 열은 연속이 아니다 (U1 해소)

3행이 헤더다. `J3 = 상반기계`, `T3 = 하반기계` 소계 열이 월 사이에 끼어 있다.

```
D:1월 E:2월 F:3월 G:4월 H:5월 I:6월 [J:상반기계] K:7월 L:8월 M:9월 N:10월 O:11월 P:12월 Q:26.1월 R:26.2월 S:26.3월 [T:하반기계] U:26년총계©
```

**"기준월 + 1, + 2" 식의 열 오프셋은 쓸 수 없다.** 3행 헤더에서 월 라벨을 직접 찾아 열을 얻어야 한다. 현재 하드코딩된 L/M/N은 8월 회차에서만 우연히 맞는다.

**기준월 판별**: `A2 = "2026-08-10(단위: 억원)"` 에 기준일이 들어 있다. 이를 파싱해 기본값으로 쓰되, 헤더에서 추출한 월 목록을 드롭다운으로 노출해 **사용자가 기준월을 선택**할 수 있게 한다. 파싱 실패해도 동작한다.

### 1-5. 📌 신규 발견 — "조달 미포함"의 실제 범위

`수입(7행)`은 순수 영업수입이 아니다. 구성이 K열 기준으로 검증됐다.

```
수입(7) = 정부출자금(8) + 국고보조금(9) + 국민주택기금(10) + 공공분양자금(13)
          + 분양회수(16) + 기타수입(28)        ← 합계가 K7과 정확히 일치 ✓
```

**국민주택기금(10행)은 인출·반납이 있는 차입성 자금이고, 정부출자금(8행)도 영업수입이 아니다.** 즉 7행에도 조달성 항목이 일부 들어 있다. `수입계(6) − 수입(7)`이 공사채·금융기관 차입(공사채·금융기관 차입)에 해당한다.

그럼에도 **7행을 기준으로 쓰는 것이 맞다.** 회의록의 169%가 정확히 7행 기준이고, 이것이 자금기획팀의 실제 판정 방식이기 때문이다. 다만 §2-3의 "조달 미포함"은 **공사채·차입을 제외한다는 의미이지, 기금·출자금까지 배제한다는 뜻이 아니다.** 코드 주석에 이 범위를 명시한다.

### 1-6. ⚠️ 연도 경계에서 월 라벨이 형식을 바꾼다

롤포워드로 열의 실제 시점을 판별했다. `P(12월) → Q(26.1월) → R → S`가 **연속**이다. 즉 `D~P`가 계획연도 1~12월이고, `Q~S`는 그 **다음 해** 1~3월인데 라벨만 `26.x월` 형식이다.

라벨 매칭 충돌 검사 결과:

| 찾는 월 | 완전 일치 | 부분 일치 |
|---|---|---|
| `1월` | `D` | `D:1월`, `O:11월`, `Q:26.1월` |
| `2월` | `E` | `E:2월`, `P:12월`, `R:26.2월` |
| `8월` | `L` | `L:8월` |

부분 일치는 `11월`이 `1월`에 걸리므로 당연히 못 쓴다. 그런데 **완전 일치도 연도 경계에서 틀린다** — 기준월이 12월이면 창은 `P(12월) → Q → R`이어야 하는데, `1월`을 완전 일치로 찾으면 8개월 과거인 `D`를 집는다.

→ **라벨 매칭만으로 3개월 창을 잡을 수 없다.** 3행을 좌→우로 훑어 소계·집계 열(`상반기계`, `하반기계`, `연간계획...`, `26년총계©`, `25년실적` 등)을 제외한 **월 열의 순서 목록**을 만들고, 기준월의 인덱스 + 다음 2개를 쓴다. 시트가 시간순으로 정렬돼 있으므로 연도 경계가 자연히 처리된다.

## 2. 확정 사항

### 2-1. 입력 형식 — xlsx
현행 `xlsx` 파싱 유지. PDF 처리 계획 없음.

### 2-2. `/aifrm` 페이지 성격 — 통합 대시보드
한 화면에서 대금 회수 위험과 유동성 Gap을 함께 본다.
- 업로드를 **이전 회차 / 최신 회차** 2개로 변경
- 유동성 Gap은 **최신 회차 파일 1개**로 산출
- 산식은 `domain/`으로, 엑셀 판독은 `infrastructure/`로 분리한다 (§3). 기존 `computeFromFiles`의 계산부가 도메인으로 간다

> **명명 주의**: 자금수지표 한 장 안에 과거 월은 실적, 이후 월은 계획이 함께 들어 있다(8월 파일 = 7월까지 실적 + 8월 이후 계획). "계획 파일 / 실적 파일"은 오해를 부르므로 **회차**로 부른다.

### 2-3. 수입 기준 — 7행 `수입`, 공사채·차입 미포함
유동성 Gap은 7행 기준으로 산출한다. 회의록의 169%가 이 기준이다.
- 제외되는 것: 공사채·금융기관 차입 (`수입계(6) − 수입(7)`)
- **제외되지 않는 것**: 국민주택기금, 정부출자금 — 7행에 이미 포함돼 있다 (§1-5)

### 2-4. 등급 기준 출처 — 회의록을 정본으로
"PRD 4장"은 저장소에 없다. 임계값이 회의록과 일치하므로 회의록을 정본으로 지정하고 코드 주석의 출처 표기를 바꾼다.

**등급 용어는 `정상 / 주의 / 경고 / 위기`로 확정** (2026-09-18). 이벤트 스토밍 문서의 `안전`·`위험` 표기는 쓰지 않는다 — 근거와 관련 명칭 정리는 [DDD 검토 §1](../design/2026-09-18-ddd-review.md) 참조.

> 판정 기준표의 정본이 원래 엑셀 시트에 있다는 점(이벤트 스토밍 6장 1번)은 후속 과제다. DDD 검토 D6 참조.

| 등급 | 기준(비율) | 화면 표시 |
|---|---|---|
| 정상 | ≥ 0.5 | ≥ 50% |
| 주의 | 0.25 ~ 0.5 | 25 ~ 50% |
| 경고 | 0.15 ~ 0.25 | 15 ~ 25% |
| 위기 | < 0.15 | < 15% |

**저장·판정은 비율로 한다.** 회의록 원문이 "0.5 이상"처럼 비율이고, 대금 회수 위험 구간(0.9/0.8/0.7)과 척도를 맞춰야 같은 구간표 타입을 공유할 수 있다. 퍼센트 변환은 화면에서만 한다.

### 2-5. 테스트 — Vitest 도입, fixtures는 gitignore
- **Vitest 도입.** 계산 순수 함수에 §4-3 케이스 5개를 자동 검증. 3단계(적정 시재 3개 모델)까지 갈 것을 고려한 선택이다.
- **실물 xlsx는 `ai-frm/fixtures/`에 두고 `.gitignore`에 추가.** 사내 자금 데이터이므로 커밋하지 않는다.
- **커밋되는 테스트·문서에는 실수치를 쓰지 않는다.** 같은 비율을 내는 합성값을 쓴다(§4-3). 단순 배수 축약(÷100)은 역산이 쉬우므로 쓰지 않는다.
- 테스트 2층 구성:
  - **계산 테스트** — 합성값, fixture 불필요, 항상 실행
  - **파싱 통합 테스트** — 실물 fixture로 `169.0% · 정상`을 확인. fixture 없으면 조건부 skip (CI·새 클론에서 깨지지 않음). 169%는 회의록에 이미 있는 값이므로 단언에 써도 무방하다

## 3. 도메인 모델

[DDD 검토](../design/2026-09-18-ddd-review.md)에 따라 3계층으로 나눈다. 지금 코드는 전부 페이지 컴포넌트 안에 있다.

```
src/
  domain/                        ← xlsx를 모른다
    risk/
      grade.ts                   등급 값 객체 + 구간 판정 (단일 정의)
      policy.ts                  구간 기준표 · 등급별 코멘트 (출처 명시)
      liquidity-gap.ts           유동성 Gap 산식
      payment-recovery.ts        대금 회수 위험 산식
    cashflow/
      statement.ts               자금수지표 회차 애그리거트
  infrastructure/
    xlsx/
      statement-reader.ts        ACL: xlsx → Statement
  app/aifrm/page.tsx             표현만
```

**합격 기준: `domain/` 아래에 `import ... from 'xlsx'`가 한 줄도 없을 것.** 이것이 지켜지면 §4-3 테스트가 fixture 없이 돈다.

### 3-1. 값 객체 — 금액과 비율을 타입으로 가른다

문제 B는 금액(억원)을 회수율로 취급해 `v >= 0.9`로 판정한 것이다. 둘 다 `number`라 타입이 막지 못했다. PoC 규모에 맞게 **브랜드 타입**으로 가른다(런타임 비용 0).

```ts
export type Amount = number & { readonly __unit: '억원' };
export type Ratio  = number & { readonly __unit: 'ratio' };   // 0.9 = 90%
```

`Amount`를 `Ratio` 자리에 넣으면 컴파일이 깨진다. 같은 실수가 다시 나오지 않는다.

### 3-2. 등급 — 단일 정의

현재 `Grade`(payment-recovery 페이지)와 `GapGrade`(대시보드)가 같은 유니온으로 두 번 선언돼 있다. 하나로 합친다.

```ts
export type Grade = '정상' | '주의' | '경고' | '위기';
export type Band  = { readonly atLeast: number; readonly grade: Grade };  // atLeast 이상 = 이 등급
export type GradeBands = readonly Band[] & { ... };   // defineBands를 통과한 것만

export function defineBands(bands: readonly Band[]): GradeBands;  // 불변식 검증
export function gradeBy(bands: GradeBands, value: Ratio): Grade;
```

`defineBands`가 **내림차순**과 **전 구간 포괄**을 강제한다. 판정이 배열 순서에 조용히 의존하던 것을 불변식으로 바꾸고, 전 구간이 덮이므로 `'위기'` 같은 기본값을 코드에 박을 필요가 없다 — 정책은 구간표가 소유한다.

`policy.ts`가 구간표를 소유한다. 출처는 회의록(§2-4)이며, 지표별 기준표 엑셀을 받으면 그쪽으로 옮긴다.

### 3-3. 회차 애그리거트

도메인의 덩어리는 **자금수지표 회차**다. 기준일 + 월 목록 + 항목 계열을 묶고 불변식을 자기 안에서 지킨다.

```ts
export type ItemName = '기초시재' | '수입계' | '수입' | '지출';

export type Statement = {
  asOf: Date;                    // A2 기준일
  baseMonth: MonthKey;           // 기준월
  months: MonthKey[];            // 시간순 월 목록 (소계 열 제외)
  amountOf(item: ItemName, month: MonthKey): Amount;
};

export function windowFrom(s: Statement, base: MonthKey, count: number): MonthKey[];
export function assertConsecutive(prev: Statement, next: Statement): Result;
```

- `windowFrom`이 3개월 창을 담당한다. **월 목록의 인덱스로 자르므로 연도 경계(§1-6)가 자연히 처리된다.**
- `assertConsecutive`가 회차 순서 검증을 맡는다. UI가 아니라 여기서 한다.

## 4. 계산 로직 (문제 A)

### 4-1. 현재 코드의 오류

```ts
const netOutflow = Math.abs(incomeSum - expenseSum);
```

`abs` 때문에 순유입 구간이 순유출로 둔갑해 수입이 많을수록 등급이 악화된다.

> 실물 확인 결과 이번 8·9·10월 창은 순유출이라 **이 파일에서는 드러나지 않는다.** 잠재 결함이며, 수정 전후로 순유출 구간의 결과는 동일하다.

### 4-2. 수정 방향

```ts
export type LiquidityGap =
  | { kind: 'gap';        openingCash: Amount; netOutflow: Amount; ratio: Ratio; grade: Grade }
  | { kind: 'net-inflow'; grade: '정상' };
```

```
순지출 = 3개월 지출(41행) − 3개월 수입(7행)      ※ 지출은 양수 (§1-2 검증)

순지출 <= 0  → { kind: 'net-inflow' }    화면에는 '해당 없음(순유입)'
순지출 >  0  → ratio = 기초시재 ÷ 순지출, §2-4 구간표로 판정
```

순유입을 **오류가 아니라 타입의 한 갈래**로 모델링한다. 현재는 `netOutflow === 0`을 "계산할 수 없습니다" 오류로 내는데, 오류가 아니라 가장 안전한 상태다.

### 4-3. 검증 케이스

`domain/`이 xlsx를 모르므로 5개 모두 순수 함수 단위로 돈다.

| # | 입력 | 기대 |
|---|---|---|
| 1 | 기초시재 1,690 / 수입 700 / 지출 1,700 (합성값) | **Gap 169.0% · 정상** (회귀 기준점) |
| 2 | 순유입 (수입 > 지출) | `net-inflow` · 정상 |
| 3 | 순지출 = 0 | `net-inflow` · 정상 (오류 아님) |
| 4 | 기초시재 0, 순지출 > 0 | Gap 0% · 위기 |
| 5 | 항목/월 누락 | 등급 대신 판독 오류 |

> 1번은 실수치가 아니라 같은 비율을 내는 합성값이다 — `1,700 − 700 = 1,000`, `1,690 ÷ 1,000 = 169.0%`.

## 5. 대금 회수 위험 (문제 B)

### 5-1. 제거 대상

`computeRecovery`는 단일 파일에서 `K7` 하나를 읽고 `plan = actual = v`, `rate = 1.0`으로 고정한 뒤 금액을 회수율처럼 판정한다. 항상 '정상'이 나오는 허위 표시이므로 함수째 삭제한다. `<details>` "자금조달 포함 기준 비교(PRD 참고)" 블록도 산출 없는 빈 껍데기이므로 함께 제거한다.

### 5-2. 대체

기존 `/aifrm/daegeum-hoe-su`의 `computeFromFiles`는 정상 동작한다. 여기서 **계산부만** 도메인으로 옮기고 파싱부는 ACL로 보낸다.

```ts
export function assessPaymentRecovery(input: { plan: Amount; actual: Amount }):
  | { kind: 'ok'; rate: Ratio; grade: Grade }
  | { kind: 'invalid'; reason: '계획값 0' };
```

- 판정 대상월 = 최신 회차의 기준월 직전 월 = **이전 회차의 기준월**
- 계획값은 이전 회차, 실적값은 최신 회차에서 같은 월을 읽는다

### 5-3. 화면 구성

```
[이전 회차 업로드]  [최신 회차 업로드]   → [산출하기]   기준월: [8월 ▾]

┌ 대금 회수 위험 ──┐  계획값 / 실적값 / 회수율 / 등급        ← 2개 회차
├ 유동성 Gap ──────┤  기초시재 / 3개월 순지출 / Gap% / 등급  ← 최신 회차
└ 종합 ────────────┘
```

- 최신 회차만: Gap은 산출, 대금회수는 "이전 회차 파일이 필요합니다" 안내
- 이전 회차만: 안내만 표시하고 Gap도 내지 않는다
- **회차 순서 검증은 `assertConsecutive`(§3-3)가 한다.** 어긋나면 경고하고, 자동 교정하지 않고 사용자 확인을 받는다

### 5-4. 상세 페이지

공용 도메인을 쓰면 `/aifrm/daegeum-hoe-su`는 대시보드의 카드와 기능이 같아진다. **대시보드로 리다이렉트**해 정리한다. 경로명도 `payment-recovery`로 바꾼다([DDD §1](../design/2026-09-18-ddd-review.md)).

### 8-2. 0단계 결과 (2026-09-18)

- **Vitest 5 + Next 16 / React 19 조합은 문제없다.** 테스트가 순수 TS라 jsdom·@testing-library·plugin-react 모두 불필요했다. `vitest` 하나만 설치했다.
- **`@types/node`를 ^20 → ^22로 올렸다.** Vitest 5의 피어 요구(`^22 || >=24`)와 충돌했는데, 실제 런타임이 Node 22이므로 `--legacy-peer-deps` 우회 대신 타입을 런타임에 맞췄다.
- **설정 파일은 `vitest.config.mts`다.** `.ts`면 CommonJS로 로드돼 ESM 문법 경고가 뜨고 향후 Vite 메이저에서 깨진다.
- `tsconfig`의 `@/*` 별칭은 Vitest가 자동으로 읽지 않아 `resolve.alias`에 직접 넣었다.
- `globals: true`를 쓰지 않는다. `include`가 `**/*.ts`라 테스트 파일이 `tsc --noEmit` 대상에 들어가므로, `vitest`에서 명시적으로 import한다.
- `src/domain/shared/smoke.test.ts`는 0단계를 green으로 검증하기 위한 임시 파일이다. **1단계에서 제거한다.**

### 8-3. 1·2단계 결과 (2026-09-18)

**순서를 바꿨다.** 원안은 `1.등급·정책 → 2.값 객체`였으나 `gradeBy`가 `Ratio`를 받아야 하므로 값 객체가 선행해야 한다. 둘은 분리해서 쌓을 수 없어 한 단계로 묶었다.

**척도를 비율로 통일했다.** 원안은 Gap을 `50/25/15`(%), 대금회수를 `0.9/0.8/0.7`(비율)로 적어 두 지표가 같은 구간표 타입을 공유할 수 없었다. 금액/비율 혼동을 타입으로 막으려던 §3-1의 취지가 여기서 무너진다. 회의록 원문이 비율이므로 비율이 정본이고, %는 표시 전용이다.

**구간표 불변식을 구조로 고정했다.** `defineBands`가 내림차순과 전 구간 포괄을 검증한다. 이로써 `gradeBy`에 기본 등급을 하드코딩할 이유가 사라졌다.

- 테스트 30개 통과. `tsc --noEmit`·`eslint` 통과
