## 0. 바뀌는 정의

기준월 t의 오차율 (자금기획팀 결정, 2026-09-28):

```
실적      = t월 회차의 (t−3, t−2, t−1)월 분양회수 실적 합
분자 계획  = t−2월 회차의 (t−1, t, t+1)월 분양회수 계획 합
분모 계획  = t−2월 회차의 (t−2, t−1, t)월 분양회수 계획 합
오차율    = (실적 − 분자 계획) ÷ 분모 계획
```

| | 지금 (엑셀과 동일) | 바뀐 뒤 |
|---|---|---|
| 7월 기준월 실적 | 5·6·7월, 각 달 직후 회차 값 | **4·5·6월, 7월 회차 한 장** |
| 7월 기준월 계획 | 5월 회차 5·6·7월 (분자·분모 같음) | 분자 **5월 회차 6·7·8월**, 분모 5월 회차 5·6·7월 |
| 이력의 단위 | 달 (실적 1개, 계획 3개/회차) | **회차** (실적 3개, 계획 4개/회차) |
| 과거 달 | 엑셀에서 옮긴 이력으로 산출 | 해당 회차 파일을 올려야 산출 (결정 (가)) |
| 엑셀과 비교 | 127개월 중 124개월 일치 | 분양회수 오차율은 엑셀과 다르다. 지수·단계도 달라진다 |

바뀌지 않는 것: ECOS 9종, 점수화 기준, 가중치, 단계, 기준월 규칙(보고월 − 2), 결측은 0이 아니라는 원칙.

## 0-1. 받은 회차에서 확인한 것 (2026-09-28)

- **1·2월 회차에는 `본운영반영` 시트가 없다.** 2026년 시트가 `12_26년자금수지표(잠정운영기준)` 하나뿐이다. 3월 회차부터 `(기본)`·`(본운영반영)`이 생긴다(본운영계획 확정). 지금 판독 계층은 `(본운영반영)`만 찾아 1·2월 회차를 못 읽는다. **`본운영반영`이 없으면 `잠정운영기준`을 읽는다**(F1a). 다른 지표에도 해당하는 수정이다.
- **1월 회차는 새 연도 파일이다.** 기준일 2026-01-09, 열은 2026년 1월 ~ `26.1월`(다음 해) 15개로 다른 회차와 같다. 기준월 열을 바르게 잡는다(R2 해소). 전년 10~12월 실적 열은 없다(`25년 실적` 연간 합계뿐). 전년 실적은 전년도 파일로 채운다 — 아직 받지 않았다.
- 8개 회차 모두 분양회수 행 15칸이 다 채워져 있다.
- **7월 예시 (정의대로 계산)**: (7월 회차 4·5·6월 실적 − 5월 회차 6·7·8월 계획) ÷ 5월 회차 5·6·7월 계획 = **+36.06%** (0점). 참고로 엑셀 방식(8월 회차 5·6·7월 실적 − 5월 회차 5·6·7월 계획)은 +23.35%. F7에서 시스템이 이 값을 내는지 고정한다.

## 1. 설계

### 1-1. 회차 기재분 (`domain/cashflow/round-entry.ts`) — 판형 2

기준월 b인 회차에서 떼어 두는 것:

```ts
type Cell = { month: YearMonth; value: Amount } | { month: YearMonth; missing: string };
type RoundEntry = {
  round: YearMonth;                       // b
  actuals: readonly [Cell, Cell, Cell];   // b−3, b−2, b−1 실적
  plans: readonly [Cell, Cell, Cell, Cell]; // b, b+1, b+2, b+3 계획
};
```

- 시트에 없는 달(1~3월 회차의 전년 실적, 다음 해 열이 없는 계획)은 `missing`과 사유다. 0으로 채우지 않는다.
- 계획 중 계획연도 끝을 넘는 칸은 표시를 남긴다(다음 해 열은 일부만 채워져 있다).

### 1-2. 분양회수 계획·실적 이력 (`domain/cashflow/forecast-ledger.ts`) — 판형 2

- **회차를 키로** 기재분을 담는다. `record(entry)`는 그 회차의 기재분을 통째로 바꾼다. 다른 회차는 건드리지 않는다.
- 조회: `entryOf(round)`, `rounds()`(올라온 회차), `latestRound()`, `missingRounds()`(첫 회차~마지막 회차 사이에 빠진 회차).
- **전년 달 실적 채우기**: 기준월 회차에 그 달 열이 없을 때만, 올린 회차 중 **그 달이 실적인 가장 최근 회차**에서 채운다. 그 회차에 열이 있는데 값을 못 읽은 경우는 채우지 않는다(결측).
- 스냅샷 판형 `version: 2`. **판형 1(지금 파일)은 새 정의로 계산할 수 없다.** 회차별 3개월 실적과 4개월 계획이 없기 때문이다. `ledgerFrom`은 판형 1을 받으면 이유를 적어 거부한다. 기존 파일은 `data/forecast-ledger.v1.json`으로 옮겨 보관한다.

### 1-3. 오차율 (`domain/risk/construction-perception/forecast-error.ts`)

- `forecastErrorAt(ledger, t)`: §0의 식. t월 회차와 t−2월 회차가 이력에 있어야 한다.
- 결측 사유는 조치가 보이게 쓴다: "7월 회차가 이력에 없습니다", "5월 회차에 8월 계획이 없습니다(다음 해 열)", "7월 회차에 전년 12월 실적이 없고, 그 달이 실적인 회차도 없습니다".
- 분모가 0 이하이면 결측이다.

### 1-4. 유스케이스·화면

- 분양회수의 "최신월"은 **이력의 마지막 회차**다. 기준월이 그보다 뒤면 "t월 회차가 이력에 없습니다. 올리세요".
- 선택 범위의 시작은 **첫 회차 + 2**다.
- **회차 올리기를 넓힌다.** 지금은 최신 회차만 이력에 반영한다. 바뀐 뒤에는
  - 이전 회차와 최신 회차를 **둘 다** 반영한다.
  - 건설경기 카드에 **"이력용 회차 추가"** 파일 입력을 둔다. 여러 파일(4월·5월 회차, 전년도 파일 등)을 한 번에 올리면 각각 반영한다.
- 이력 안내: 올라온 회차 목록과, 지금 기준월에 필요한 두 회차 중 빠진 것("6월 기준월에는 4월·6월 회차가 필요합니다 — 4월 회차 없음").

### 1-5. 검증

- **엑셀 동등성(W6)을 둘로 나눈다.**
  - ECOS 9종과 산식: 엑셀의 분양회수 오차율(라벨 보정)을 **그대로 넣어** 127개월 지수·단계가 엑셀과 같은지 본다. 산식 동등성은 계속 지킨다.
  - 분양회수 오차율: 엑셀과 다른 것이 정상이다. 대신 **자금기획팀 예시(7월)** 를 기대값으로 삼는다(§3 F7).
- **시드 스크립트**는 이력을 더 이상 만들지 않는다. fixture 추출만 한다.

## 6. 재개정 — 엑셀 분양회수data와 같게 (2026-09-28)

자금기획팀이 보낸 `분양회수data` 이미지와 §0의 식이 달랐다(7월 36.06% vs 11.35%). 한 단계씩 바꿔 계산해 원인을 가렸다.

| 단계 | 계산 | 7월 |
|---|---|---|
| 엑셀 이미지 "2026/07" 행 | | 11.35% |
| 엑셀식 재현 | 4·5·6월 실적 − **4월 회차** 4·5·6월 계획, 같은 계획으로 나눔 | 11.35% |
| 실적을 7월 회차 한 장으로 | 나중 회차의 정산 실적(합 2.24% 차이) | 13.84% |
| 계획을 5월 회차 5·6·7월로 | 엑셀 "2026/05" 행 라벨을 그대로 읽은 것 | 36.11% |

**원인**: 엑셀 행 라벨이 한 달 밀려 있다(정책 §7 D8). "2026/05" 행의 계획 M0~M2는 5월 회차가 아니라 **4월 회차**의 4·5·6월 계획이다. 서술은 이 라벨을 읽은 것이었다.

**확정한 정의** (정책 §3-2): 기준월 t = (t−3~t−1월 실적 − t−3월 회차의 t−3~t−1월 계획) ÷ 같은 계획. 실적은 각 달의 직후 회차 값. "7월 오차율"(엑셀 "2026/07" 행)은 7월 기준월에 쓴다. 필요한 회차는 t−3~t월 네 개.

**구현** (`147f5c7`): 이력의 판형은 그대로다(회차마다 시트의 실적 전부와 계획 4칸) — 필요한 값이 이미 있어 쌓인 회차를 다시 올리지 않았다. 실적 조회를 직후 회차 값(`actualOf`)으로, 계획을 t−3월 회차의 M0~M2로 바꿨다. 선택 범위 시작 = 첫 회차 + 3.

**엑셀 `위기단계`와의 차이**: 엑셀 `위기단계`는 7월 지수에 "2026/08" 행(24.11%)을 쓴다. 이 지표는 결정대로 "2026/07" 행(11.35%)을 7월에 쓴다. 산식 동등성 테스트(엑셀 오차율 주입)는 엑셀 자체의 대응을 검증하는 것이라 그대로 둔다.
