# 대금 회수 위험 1단계 — 구현 계획 초안

**작성일**: 2026-09-09  
**대상 기능**: 대금 회수 위험 등급 자동 출력 (1단계)  
**프로젝트**: ai-frm 내 `/aifrm/` 경로에서 진행  
**MVP 판정 기준 시점**: 8월 기준 → 7월 판정 (7월 계획 vs 7월 실적)

---

## 1. 기능 개요 (한 줄)

7월 자금수지표(계획)와 8월 자금수지표(실적)의 `12_26년자금수지표(본운영반영)` 시트에서 **'수입' 항목값**을 읽어 **회수율**을 계산하고, 4단계 등급(정상/주의/경고/위기)을 웹 화면에서 자동 출력한다.

---

## 2. 입력·계산·출력 정의

### 2-1. 입력 파일 2종 (브라우저 업로드)

| 구분 | 파일 (예시) | 시트 | 읽는 기준 | 의미 |
|---|---|---|---|---|
| **계획** | `2026년 7,8,9월 계획 ★01-01. 2026 본운영계획 자금수지표(0708_v1).xlsx` | `12_26년자금수지표(본운영반영)` | **'수입' 항목값** | 7월 대금 회수 계획값 |
| **실적** | `2026년 8,9,10월 계획 ★01-01. 2026 본운영계획 자금수지표(0818_v1)_법인세추가.xlsx` | `12_26년자금수지표(본운영반영)` | **'수입' 항목값** | 7월 대금 회수 실적값 |

- 1단계 MVP 대상 월: **7월**
- 실적값 출처: 8월 파일(7월 실적값이 그 파일에 포함됨)
- 계획값 출처: 7월 파일
- 읽는 방식: **셀 위치 고정이 아니라 '수입' 항목명으로 찾는다** (매월 위치 변동 대응)

### 2-2. 읽기 방식 (위치 변동 대응)

셀 위치는 매월 바뀐다(8월 시점 K7, 9월 시점 L7 예정 등).  
따라서 1단계에서는 아래 방식으로 읽는다.

1. 시트 `12_26년자금수지표(본운영반영)`를 연다
2. **항목명 '수입'을 찾는다**
3. 찾은 '수입' 항목이 가리키는 **값 셀**을 읽는다
4. 그 값이 해당 파일의 '수입' 항목값이다

> 시트 구조가 "행=항목명, 열=월"인지, 혹은 다른 구조인지는 실제 엑셀을 보고 확정한다. 지금은 "수입 항목값을 찾는다"는 기준으로 MVP를 잡는다.

### 2-3. 계산 공식

```
회수율 = 실적(8월 파일의 '수입' 값) ÷ 계획(7월 파일의 '수입' 값)
```

### 2-4. 등급 판정 기준

| 회수율 구간 | 등급 |
|---|---|
| ≥ 0.9 | 정상 |
| ≥ 0.8 그리고 < 0.9 | 주의 |
| ≥ 0.7 그리고 < 0.8 | 경고 |
| < 0.7 | 위기 |

### 2-5. 출력 (웹 화면)

Next.js 웹 페이지 하나에 아래를 표시한다. **화면 표시만**으로 1단계는 끝낸다(내보내기/공유는 제외).

- 읽은 계획값 / 실적값
- 계산된 회수율
- 판정 등급 (4단계 중 하나)
- 판정 기준이 보이는 UI면 더 좋음 (MVP 이후 개선)

초기 MVP에서는 "기본값(고정 문구)" 수준의 결과 문구로도 충분.

---

## 3. 단계별 구현 작업 (1단계)

### 3-1. 준비 사항

- `ai-frm` 프로젝트 내 `/aifrm/` 경로 생성 (또는 Pages/Route 위치로 확정)
- 엑셀 읽기용 라이브러리 결정 및 설치 (예: `xlsx`/`exceljs` 계열 또는 Node에서 읽히는 패키지)
- 개발 환경에서 실제 엑셀 2개 파일로 테스트할 수 있게 준비

### 3-2. 핵심 구현 단계

1. **입력 방식 구현 (파일 업로드 2개)**
   - 사용자가 브라우저에서 계획 파일 1개, 실적 파일 1개를 업로드
   - 서버는 업로드된 엑셀을 읽어서 '수입' 항목값을 추출

2. **'수입' 항목값 찾기 로직 구현**
   - 시트 `12_26년자금수지표(본운영반영)`를 기준으로
   - 항목명 '수입'을 찾고, 해당 항목의 값을 읽는다
   - 읽기 결과 검증:
     - 시트가 없을 때
     - '수입' 항목이 없을 때
     - 값이 비어 있거나 숫자가 아닐 때
     - 계획값이 0이어서 나눗셈이 안 될 때
   - 검증 실패 시 등급을 내지 말고 "입력 오류" 형태로 웹에 표시

3. **회수율·등급 계산 로직 구현**
   - 회수율 계산 → 구간 판정 → 등급 반환
   - 결과는 계획값, 실적값, 회수율, 등급을 묶은 객체/레코드로 정리

4. **웹 출력 페이지 구현**
   - 파일 2개 업로드 → 파싱·계산 → 결과 표시 흐름
   - 결과 표시 항목: 계획값, 실적값, 회수율, 등급, 판정 근거(구간), 고정 문구 코멘트
   - 오류 시 사용자 친화적 메시지

5. **MVP 확인 항목**
   - 실제 7월·8월 파일 2개로 정상 케이스가 등급까지 잘 나오는지
   - 계획값 0, 빈 값, 시트 없음, '수입' 항목 없음 같은 예외에서 오류 처리가 되는지

---

## 4. 출력 예시 (초안)

```
[대금 회수 위험 판정 결과]

판정 기준월: 7월
기준 설명: 7월 계획 대비 7월 실적

계획값: (7월 파일 '수입' 항목값)
실적값: (8월 파일 '수입' 항목값)
회수율: (실적 ÷ 계획)

판정 등급: 정상 / 주의 / 경고 / 위기

판정 근거: 회수율 ○○ → 해당 구간

기본 코멘트: (초기 고정 문구, 등급별 1문장)
```

초기에는 문구 자체를 기본값(고정)으로 두고, 이후 품질 개선 단계에서 교체 가능한 구조로 둔다.

---

## 5. 결과 문구 설계 (3번 상세)

### 5-1. MVP 단계 문구 원칙

- 초기 MVP에서는 **고정값(하드코딩)**으로 둔다
- 사람이 쓰던 FRM 보고서의 문체를 참고해서 기본 문장을 만든다
- 추후 교체 가능한 구조(설정 파일/DB 등)로 빼 둔다

### 5-2. MVP에서 표시할 문장 구성

최소한 아래 정보가 화면에 드러나면 된다.

1. 판정 대상 월과 기준
2. 계획값·실적값
3. 회수율
4. 등급
5. 한 줄 코멘트(초기 기본값)

### 5-3. 등급별 기본 코멘트 초안(초기 고정값 후보)

실제 문구는 아직 확정 전이므로, MVP용 참고 예시다.

- 정상: 계획 대비 실적이 양호합니다.
- 주의: 계획 대비 실적이 다소 낮습니다. 추이를 확인하세요.
- 경고: 계획 대비 실적 미달이 분명합니다. 원인을 점검하세요.
- 위기: 계획 대비 실적 미달이 큽니다. 즉시 대응이 필요합니다.

이건 **예시**고 실제 문구는 확정 후에 넣어야 한다.

### 5-4. 누가/어떻게 정하나

- 초기 고정 문구: 자금기획팀 또는 요청팀이 등급별로 한 문장씩 제공한다
- MVP에서는 그 문장을 코드에 상수처럼 넣고, 이후 단계에서 외부 설정으로 빼서 교체 가능하게 설계한다
- 보고서 전체 문구와 등급별 한 줄 코멘트가 같은지/다른지도 나중에 확인한다 — 다르면 분리해서 관리한다

### 5-5. 1단계 저장/공유 범위

- **웹 화면 표시만**으로 끝낸다
- 텍스트 내보내기, 사내 게시판 공유, FRM 보고서 자동 반영은 1단계 이후에 넣을지 여부만 추후 결정 (지금 범위에서는 제외)

---

## 6. MVP 범위 경계 (1단계 한정)

### 포함

- 엑셀 2개 파일 업로드 → '수입' 항목값 읽기
- 회수율 계산 + 4단계 등급 판정
- 결과를 웹 화면에 표시 (고정 문구 포함)

### 제외 (후순위/별도)

- 유동성 갭(2단계)
- 적정 시재·3개 모델(3단계)
- 월별 FRM 보고서 자동 생성 (1단계 이후)
- 일별 경제 시황 모니터링 (별도 업무)
- 운영 계획 자동화 (범위 제외)
- 매달 자동으로 서버 파일 읽기(운영 자동화 영역과 겹침)

---

## 7. 확정되지 않은 것 / 확인 필요

- 시트 `12_26년자금수지표(본운영반영)`의 실제 구조(행/열 배치)가 어떤지 — "수입" 항목값을 찾는 정확한 위치를 확정하려면 실물 확인 필요
- 이번 회차 시트의 '수입' 항목값 셀 위치(예: 8월 시점 K7)가 다음 회차에도 같은 항목 위치를 유지하는지
- 결과 표시 문구(초기 기본값)를 누가/어떤 내용으로 정할지 (MVP에서 쓸 등급별 한 줄 코멘트 원문)
- 판정 결과가 FRM 보고서나 타 시스템과 이어지는지 (1단계에서는 단순 표시로 충분한지)
