# AIFRM — 월별 자금 리스크 모니터링

자금수지표 회차와 한국은행 ECOS 지표로 네 지표를 판정한다.

| 지표 | 입력 | 판정 |
|---|---|---|
| 대금 회수 위험 | 연속한 두 회차 (7월 판단 = 6월 계획 vs 6월 실적) | 4단계 등급 |
| 유동성 Gap | 최신 회차 | 4단계 등급 |
| 적정 시재 | 최신 회차 | 안정적 / 적정시재 부족 |
| 건설경기 인식 지수 | ECOS 9종 + 올린 회차 네 개의 분양회수 | 종합위기단계(4단계) |

정책과 설계는 저장소 루트의 `docs/`에 있다. 건설경기 인식 지수는
`docs/plans/2026-09-28-geonseol-gyeonggi-policy.md`와 같은 폴더의 `-impl-plan.md`를 본다.

## 실행

```bash
npm install
npm run dev
```

`http://localhost:3000/aifrm`을 연다.

검증: `npm run verify`(tsc + vitest), `npx eslint src`.

## ECOS 인증키

건설경기 인식 지수는 서버가 한국은행 ECOS Open API를 부른다. 키가 없으면 카드가
산출불가와 함께 "ECOS_API_KEY가 설정되지 않았습니다"를 보인다.

1. https://ecos.bok.or.kr/api/ → 서비스 이용 → 인증키 신청(무료, 즉시 발급).
2. 이 폴더의 `.env.local`에 한 줄을 넣는다. `.env*`는 커밋되지 않는다.

   ```
   ECOS_API_KEY=발급받은키
   ```

키는 서버(`src/app/api/_lib/composition.ts`)에서만 읽는다. `NEXT_PUBLIC_` 접두어를
붙이지 않는다 — 붙이면 브라우저 번들에 들어간다.

## 건설경기 인식 지수의 기준월

기준월 = 올린 최신 회차 − 2개월이다. 8월 기준(최신 회차 8월)이면 6월, 7월 기준이면 5월이다.
8월 기준은 5·6·7·8월 회차를 올린다 — 이 네 개로 모든 지표가 채워진다. 카드의 **건설경기 기준월** 선택 상자로 다른 달을 볼 수 있다. 회차를
새로 올리면 기본값으로 돌아간다. 회차 없이 API를 부르면 오늘이 속한 달 − 2개월이다. 유동성 Gap·적정 시재의 **Gap·시재 기준월**(기본값 최신 회차의
기준월)과는 따로 움직인다. 화면의 달은 모두 `YYYY/MM`으로 보인다.

고른 달의 값이 아직 없으면 이전 달로 옮기지 않고 산출불가와 사유(공표 전 / 조회
실패 / 필요한 회차)를 보인다. 건설·주택 통계는 익월 말에 수록되므로, 기준월이 아직
공표 전이면 그 지표들이 "공표 전"으로 나온다. 과거 달은 지금의 ECOS 값으로 계산하므로 당시 보고한
값과 다를 수 있다. ECOS 응답은 서버에서 10분 동안 재사용한다.

## 분양회수 예측오차 — 회차 네 개

분양회수 예측오차(기준월 t)는 엑셀 `분양회수data`와 같은 정의로 계산한다.

```
(t−3~t−1월 실적 − t−3월 회차의 t−3~t−1월 계획) ÷ 같은 계획     실적은 각 달의 직후 회차 값
7월 = (4·5·6월 실적 − 4월 회차 4·5·6월 계획) ÷ 같은 계획 = 엑셀 "2026/07" 행
```

라벨 t는 엑셀 `분양회수data` 행 라벨이다(실적이 t−1에서 끝난다). N월 기준(기준월 N−2)에는
**"N" 행**을 쓴다 — 8월 기준이면 5월 회차 5·6·7월 계획 대비 5·6·7월 실적 = "2026/08" 행.
엑셀 `위기단계`는 기준월에 한 달 앞 행(6월 지수에 "2026/07")을 써서 한 달 다르다.

그래서 행 t마다 **t−3 ~ t월 회차 네 개**, N월 기준에는 N−3 ~ N월 회차 네 개가 필요하다. 회차가 바뀔 때마다 앞 달 실적이
조금씩 고쳐지므로, 실적을 직후 회차에서 읽어야 엑셀과 같다.

**회차는 저장하지 않는다.** 화면에 올린 회차만으로 매번 계산한다. 브라우저가 각 회차에서
분양회수 실적(1월~직전 달)과 계획만 떼어 산출 요청에 담아 보낸다. 파일 원본은 서버로
가지 않고, 서버도 아무것도 남기지 않는다. 새로고침하면 다시 올린다.

- 파일은 페이지 위쪽 **"자금수지표 회차"** 한 곳에서 여러 개를 한 번에 올린다. 가장 늦은
  회차가 최신 회차, 바로 전 달 회차가 이전 회차가 되고, 올린 회차 전부가 분양회수에 쓰인다.
- 고르면 바로 읽어, 산출 전에 지표마다 필요한 회차와 빠진 회차를 표로 보인다. 최신 회차가
  L이면 Gap·시재는 L, 대금 회수 위험은 L−1·L, 건설경기(기본 기준월 L−2)는 L−3 ~ L이다.
- 1~3월 기준월은 전년 10~12월 회차(계획)와 전년 달 실적이 필요하다. 전년도 파일을 올린다.

1·2월 회차는 `잠정운영기준` 시트, 3월 회차부터는 `본운영반영` 시트를 읽는다.

### 엑셀 동등성 fixture

```bash
node scripts/extract-perception-fixtures.mjs "<3. 건설경기인식지수(2026).xlsx>"
```

ECOS 9종과 산식이 엑셀과 같은지 검증할 fixture를 `fixtures/`에 만든다. 분양회수
예측오차는 `fixtures/자금수지표`의 회차 파일로 계산한 값을 엑셀 `분양회수data`와
비교한다. 앱은 `분양회수data` 시트를 읽지 않는다.

## 사내 데이터

`fixtures/`(자금수지표 회차, 엑셀 기대값)는 커밋하지 않는다.
이 파일이 있을 때만 도는 테스트가 있고, 없으면 건너뛴다.
