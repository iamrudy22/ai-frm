# 이벤트 스토밍 결과 정리 (2회차 · 2026-09-09)

> **이 문서의 용도**: 2회차 오프라인 세션에서 화이트보드에 붙인 포스트잇과 회의 논의를 텍스트로 옮긴 것이다.
> PRD를 쓸 때 화면 대신 이 문서를 옆에 열어 두고 참고하면 된다. 사진을 못 여는 환경(사내 PC 등)에서도 같은 내용을 볼 수 있게 만든 재료 문서다.
> 여기 적힌 내용은 **확정 스펙이 아니라 현행 업무의 기술(記述)**이다. 무엇을 자동화 범위에 넣을지는 PRD에서 정한다.

## 0. 한 장 요약

현재 자금기획팀의 **월별 자금 리스크 모니터링**은 네 덩어리로 굴러간다.

```
[1] 수집 ──────────> [2] 산출 ──────> [3] 등급 판정 ──────> [4] 리포팅
 내부: 사내시스템        엑셀 3종         지표별 4단계          FRM 보고서
 외부: ECOS·국토부                       (안전/주의/경고/위험)   → 부서장 판단
                                                             → 조달팀·예산팀 연계
```

자동화의 1차 목표는 **[1] 수집부터 [3] 등급 판정까지를 프로그램으로 대체**하고, [4]는 기존 보고서 양식대로 자동 생성하는 것이다. 프로젝트명은 **AIFRM**으로 정했다.

## 1. 화이트보드 복원

포스트잇과 화살표를 흐름대로 옮겼다. 왼쪽에서 오른쪽으로 읽는다.

### 1-1. 수집 (좌측 영역)

```
[외부 자료]
  ECOS(한국은행) ──┐
                   ├──> (수기 입력) ──> 사내 엑셀
  국토부 자료    ──┘
   · 자료 조회 후 검색·선별
   · 엑셀 다운로드가 안 되는 사이트는 필요한 값만 골라 손으로 옮김

[내부 자료]
  사내 시스템 ──> 담당자(지출 원인자) 입력분 Download
             ──> 수입·지출 현황 + 계획 대비 실적
             ──> **자금 수집표** 작성
                  · 전사 현금흐름을 세부 항목별로 정리한 서머리 포맷
                  · 월 1회 작성
                  · 상위 5개 항목 금액 적정성 수기 검토
```

붙어 있던 포스트잇 문구(원문에 가깝게):
- "내부 자료 수집: 담당자별 시스템에 해당하는 지출 계획 예산, 전사 수입·지출 자료 취합"
- "자금계획 취합 → 각 항목 단위 기준 금액 비교 분석 → 항목 발생 시점 모니터링 관리"
- "자금 수집표 검색"
- "수입·지출 현황 자료: 결재선이 기한에 맞춰 사내 데이터 반영"
- "ECOS 자료(월별 조회), 검색"
- "국토부 자료, 검색"

### 1-2. 산출 (중앙 영역)

```
자금계획 취합 ──> 계획·실적 예상액 ──> 비교 분석 ──> 자금 리포팅
                    (Download)              │
                                            ├──> 대금 회수 위험 ──> [유동성 Gap 산출]
                                            ├──> 적정 시재      ──> [적정 시재 산출]
                                            └──> 현재 시재      ──> [현재 시재와 비교]

ECOS·국토부 ──> 건설경기 인식 지수 ──> [건설경기 지수 산출]
                                   └──> [조달 위험 산출]
```

### 1-3. 등급 판정 (우측 영역)

```
4개 산출물 ──> 지표별 점수 계산 ──> 위험 단계 구분
                                    (안전 / 주의 / 경고 / 위험)
```

포스트잇 문구:
- "지표별 점수 개념 / 지표별 정성 기준 (안전·주의·경고·위험)"
- "위험 단계 구분"

### 1-4. 리포팅·매뉴얼 (최우측 영역)

```
위험 단계 판정 ──> 월별 FRM 보고서(그래프 포함) ──> 부서장 최종 판단
                                                  ├──> 조달팀 (자금 조달)
                                                  └──> 예산팀 (예산 연계)

경고·위험 단계 ──> Contingency Plan 시나리오 (현행화 예정)
```

포스트잇 문구:
- "보고서 어떤 그래프 넣을지"
- "보고서 저장·공유 (사내 게시판)"
- "위험 → contingency plan 시나리오"
- "예산팀 자금 검토 의뢰"

## 2. 단계별 상세

### 2-1. 정보 수집

수집은 내부 자료와 외부 자료로 나뉘어 병렬로 진행된다.

**내부 자료 수집**
- 사내 시스템에서 각 담당자(지출 원인자)가 입력한 데이터를 다운로드한다.
- 수입·지출 현황 및 계획 대비 실적 데이터를 취합해 **자금 수집표**를 만든다.
- 자금 수집표는 전사현금흐름을 세부 항목별로 정리한 요약 표(서머리 포맷)이며 매월 작성한다.
- 분석할 때는 상위 5개 항목의 금액 적정성을 확인하고 오류를 수기로 검토한다.

**외부 자료 수집**
- 한국은행 통계(ECOS)와 국토부 자료를 해당 사이트에서 직접 조회해 사내 엑셀에 손으로 입력한다.
- 엑셀 다운로드가 안 되는 경우(ECOS처럼 항목별 구성이 다른 사이트)에는 필요한 값만 골라 수동으로 넣는다.

### 2-2. 산출: 엑셀 3종

수집한 자료로 아래 세 개의 시트를 만든다.

| 시트명 | 원천 자료 | 산출 지표 |
|---|---|---|
| **건설 경기 인식 지수** | ECOS, 국토부 등 외부 자료 | 건설 경기 지수 |
| **대금 회수 위험** | 내부 자료 | 대금 회수 불능 위험, 유동성 Gap |
| **적정 시재** | 내부 자료 + 현재 시재 | 적정 보유 잔고 대비 현재 시재 |

- **적정 시재 산출 방식**: 향후 3개월간 예상 지출액을 산출해 현재 보유 자금과 비교한다. 보유액이 더 많으면 적정, 부족하면 자금 조달이 필요하다.
- **정기 모니터링**: 전월 계획 대비 당월 실적을 매월 비교한다. 예를 들어 7월 말에 8월 계획을 세우고, 8월 말에 실적과 대조한다.

### 2-3. 위험 단계 구분

네 가지 지표(건설 경기 인식 지수, 대금 회수 위험, 유동성 Gap, 적정 시재)를 **각각 독립적으로** 평가해 단계를 매긴다.

- 종합 점수 하나로 합산하는 방식이 아니라 **지표별 개별 단계 판정**이다.
- 각 지표의 점수 기준표는 해당 엑셀 시트 안에 들어 있다.
- 단계는 안전 / 주의 / 경고 / 위험이다.

> 📌 1회차에서 들었던 "17개 지표 · 가중치 100점 만점" 체계와 이번에 정리된 "지표별 개별 판정"의 관계를 PRD에서 한 번 더 확인해야 한다. 상위 체계와 이번 4개 지표가 어떤 관계인지가 스코프에 직결된다.

### 2-4. 보고서 작성 및 보고

- 위험 단계 판정 결과와 그래프를 담은 **월별 FRM(Financial Risk Management) 보고서**를 작성한다.
- 보고서는 부서장에게 제출하고, 부서장이 최종 판단을 내린다.
- 위험 단계별 액션 플랜 매뉴얼이 있으나 일부가 미비해서 **현행화 작업 예정**이다.
- 자금 조달 관련 사항은 **조달팀**에 보고서를 전달하고, 예산 관련 사항은 **예산팀**으로 연계한다.
- 조달 시점 판단용 인사이트(다음 달 예상 부족액, 조달 규모 등)는 자금 수집표의 수입·지출 데이터만으로도 낼 수 있다.

## 4. 합의된 자동화 방향

| 항목 | 합의 내용 |
|---|---|
| **1차 목표** | 외부 사이트 데이터 입력 → 엑셀 3종 산출 → 위험 등급 판정까지의 로직을 프로그램으로 구현 |
| **보고서** | 월별 보고서 샘플을 기준으로 같은 형식이 자동 생성되게 한다 |
| **보고서 문구** | 초기에는 기본값(고정 문구)으로 두고, 이후 품질 개선 단계에서 교체 가능한 구조로 설계 |
| **일별 경제 시황** | 국고채 1·3·5년물 금리, 주가지수, 환율, 회사채 스프레드 등. **월별 FRM과 별개 업무**로 분리하고 크롤링으로 자동화 |
| **프로젝트명** | AIFRM |

## 5. PRD 항목별 재료 매핑

이 문서의 어느 부분이 PRD 어디로 들어가는지 정리했다. PRD를 쓸 때 이 표를 따라가면 된다.

| PRD 항목 | 이 문서에서 가져올 재료 | 상태 |
|---|---|---|
| 1.1 한 줄 정의 | 4장 1차 목표 문장 | 재료 있음 |
| 1.2 해결 문제·핵심 가치 | 2-1 수기 입력·수기 검토 대목 (휴먼 에러, 시간 소요) | 재료 있음 |
| 1.3 대상 사용자·이해관계자 | 작성자=자금기획팀 담당자, 승인자=부서장, 연계=조달팀·예산팀 | 재료 있음 |
| 2.1 한다 / 하지 않는다 | "등급 판정까지 자동, 최종 판단은 부서장" | **결정 필요** |
| 3.1 핵심 기능 (F1~) | 1-1~1-4의 네 덩어리를 기능 단위로 쪼갠다 | 재료 있음 |
| 3.2 기능별 입출력 | 2-2 엑셀 3종 표 (원천 → 산출 지표) | 재료 있음 |
| 3.3 사용자 시나리오 | 0장 한 장 요약의 좌→우 흐름 | 재료 있음 |
| 4.5 데이터·지식원 | ECOS, 국토부, 사내 시스템 다운로드분, 자금 수집표 | 재료 있음 |
| 4.6 제약·예외 | 사이트 구조 변경 시 크롤링 실패, 민감정보 반출 | **결정 필요** |
| 5.1 MVP 범위 | 4장 1차 목표 (수집→산출→판정). 보고서 문구는 고정값 | 재료 있음 |
| 5.2 로드맵 | ①샘플 엑셀로 산출·판정 → ②보고서 자동 생성 → ③외부 수집 자동화 → ④일별 시황 | 재료 있음 |
| 5.3 성공 기준 | 사람이 만든 이번 달 보고서와 프로그램 출력이 얼마나 일치하는가 | **결정 필요** |

## 6. 아직 정하지 않은 것

PRD를 쓰면서 팀이 답을 채워야 하는 항목이다. 여기가 비어 있으면 구현에서 막힌다.

| # | 열린 질문 | 왜 필요한가 |
|---|---|---|
| 1 | 4개 지표 각각의 **점수 산식과 구간 기준**을 그대로 옮겨 쓸 수 있게 문서화할 수 있는가 | 엑셀 시트 안에 있다고 했으나, 프로그램으로 옮기려면 수식과 임계값이 명시돼야 한다 |
| 2 | 1회차의 **17개 지표 체계**와 이번 4개 지표는 어떤 관계인가 | 부분 구현 시 점수를 어떻게 낼지가 여기서 정해진다 |
| 3 | **자금 수집표 실제 샘플**(비식별화)을 받을 수 있는가 | 입력 스키마를 이 파일로 정의한다 |
| 4 | **FRM 보고서 실물 샘플** 1부 | 출력 포맷과 그래프 종류를 여기서 역산한다 |
| 5 | ECOS·국토부에서 실제로 쓰는 **항목명과 조회 경로** | 크롤링·API 대상을 특정해야 자동화가 가능하다 |
| 6 | 액션 플랜 매뉴얼을 **어느 시점 버전으로 고정**할 것인가 | 현행화 중인 규칙 위에 PoC를 세우게 된다 |
| 7 | 보고서 기본 문구를 누가 어떤 기준으로 정할 것인가 | MVP에서는 고정값이라도 원문이 필요하다 |
| 8 | 일별 경제 시황을 이번 PoC 범위에 넣을 것인가 | 별개 업무로 정리됐으므로 스코프 밖으로 뺄지 결정한다 |
